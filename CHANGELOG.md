## [Unreleased]

### Added (Sprint 9 — tickets + audit log, slices 9.A–9.F)

- **Audit-log helper** (`apps/api/src/lib/audit.ts`). `writeAuditLog({ type, request, ... })` captures `request.ip` (honors `trustProxy: true`) and `user-agent` (truncated to 500 chars), soft-fails so a transient DB hiccup on the audit row never breaks the user action. Transactional variant `writeAuditLogTx(tx, args)` for spots that already wrap in `prisma.$transaction`. Wired into `PASSWORD_CHANGED` (me/password), `TOTP_ENABLED` / `TOTP_DISABLED` (two-factor enroll/disable), `PROPERTY_DELETED` (soft-delete route), and `SUPER_ADMIN_BULK_OPERATION` (ticket assign).
- **Schemas** (`packages/shared/src/schemas/ticket.ts` + `.../audit.ts`). `ticketSchemas` covers Ticket CRUD + reply + assign + status-change inputs, the per-message attachment shape (`{mediaObjectId, name, size, mimeType, url}`), and a server-computed `callerActions` block (canReply / canAssign / canChangeStatus / canSeeInternal) so the UI doesn't replicate the role-and-status gate. `auditSchemas` mirrors `AuditEventType` from Prisma + the cursor-paginated viewer query/response shape.
- **Tickets API** (`/api/dashboard/tickets/*`). Visibility scoped per role: AGENT sees own; AGENCY_ADMIN sees their agency's; SUPER_ADMIN sees all. List endpoint cursor-paginates on `(lastActivityAt desc, id desc)` with status / priority / category filters + free-text on subject + super-admin-only `agencyId` / `assignedToId` filters. Detail returns the full message thread with `isInternal` notes filtered out for non-super-admin readers (defence-in-depth on top of the role check). Create wraps the first `TicketMessage` in the same `prisma.$transaction` as the `Ticket` so partial inserts are impossible. Reply auto-bumps `lastActivityAt`, promotes `RESOLVED` → `IN_PROGRESS` when a customer replies (so super-admin sees re-engagement), and promotes `OPEN` → `IN_PROGRESS` on the first super-admin reply. Assign is super-admin-only; targets must have `role=SUPER_ADMIN` (no leaking customer tickets to AGENT users). Status transitions are super-admin-only with auto-stamping of `resolvedAt` / `closedAt`.
- **Ticket attachments via R2**. Re-uses the existing `/api/uploads/sign` + `/api/uploads/register` pipeline. `TicketMessage.attachments` JSON stores `{mediaObjectId, name, size, mimeType, r2Key}`; on attach we `MediaObject.refCount++` + clear `scheduledDeleteAt` inside the same transaction so the cleanup worker doesn't reap. Client supplies the cap (5 attachments / 10MB each via the existing api caps); UI uploader integration deferred to follow-up.
- **AuditLog viewer** (`/api/dashboard/admin/audit-log`). Super-admin-only. Cursor-paginated. Filters: event type / actor email (substring + insensitive) / agency / target kind / from-date / to-date. Returns flattened actor email + agency name from the `actor.agency` relation so the UI doesn't have to round-trip per row.
- **Web `/dashboard/tickets`** — list (status filter + subject search + cursor pagination, status + priority chips, message count + last-activity timestamp), `/new` (subject + category + priority + body form via `useActionState`), `/[id]` thread view (color-coded status badge, internal-note tinting in amber, attachment links rendered through the storage `publicUrl`, reply form with super-admin-only `isInternal` toggle, super-admin-only status-transition button row that surfaces only the targets reachable from the current state).
- **Web `/dashboard/admin/audit-log`** — super-admin-only. Filter row (type select + actor email + agencyId + targetKind), table with relative timestamps, type badge, IP-under-actor, truncated metadata JSON. Cursor pagination carries filters forward. Admin landing tile added.
- **Web dashboard tiles**. Tickets tile on dashboard home (visible to all roles). Tickets queue + Audit log tiles on admin landing.
- **i18n**. New 4-locale `tickets` + `audit` namespaces in `apps/web/messages/{en,es,de,fr}.json`.

### Added (Sprint 8 — marketing, slices 8.A–8.K)

- **Schema additions**. Migration `20260510170000_sprint_8_marketing` adds the `Contact` model (`@@unique(agencyId, email)`, indexed on `(agencyId, createdAt desc, id desc)` for cursor lists, free-form `tags String[]` driving recipientFilter, GDPR-aware `consentGivenAt` + `unsubscribedAt`), `EmailCampaignRecipient.context Json` (per-recipient render snapshot taken at materialize time so edits to Contact don't drift already-sent emails), and `@@unique(campaignId, email)` on `EmailCampaignRecipient` so the dispatcher can `createMany skipDuplicates` and double-clicks of "send now" collapse into one row. Existing `AgencyEmailConfig`, `AgencyEmailDomain`, `EmailTemplate`, `EmailCampaign`, `EmailSuppression`, `FeaturedListing` from Sprint 0 unchanged.
- **HMAC tracking tokens** (`packages/auth/src/tokens.ts`). `signTrackingToken({k,r,c?})` + `verifyTrackingToken` produce compact `<base64url(payload)>.<base64url(hmac)>` strings used by the open / click / unsubscribe surfaces. `kind` discriminator prevents cross-flow reuse. `timingSafeEqual` for verification. Re-uses `ENCRYPTION_KEY` as the HMAC secret (same trust boundary; no extra env var).
- **Marketing schemas** (`packages/shared/src/schemas/marketing.ts`). Full Zod surface for email config (with `hasPassword` + `hasDkimKey` flags so the api never returns ciphertext), email domains (records-array projection containing TXT for VERIFY/SPF/DMARC + CNAME-style DKIM), email templates, email campaigns (status enum + recipient-filter discriminated source `contacts | leads`), email suppressions, contacts, featured listings (surface enum + source enum), and the public featured-card projection.
- **Marketing API** (`/api/dashboard/marketing/*`). Every route gated behind `requireFeature("feature:marketing.*")` — FREE returns 403 PLAN_REQUIRED. Endpoints: `email-config` (GET/PUT/DELETE — AES-256-GCM encrypts `smtpPassword` and `dkimPrivateKey` on persist; password omitted on update keeps the existing ciphertext), `email-config/test-send` (synchronous nodemailer 6.x send to caller's email; persists `testStatus` + `testedAt`), `email-domains` (CRUD + `:id/verify` does live `dns/promises.resolveTxt` for SPF / DKIM / DMARC / our `_inmolink.<domain>` verification record + flips per-record statuses), `email-domains/dkim/rotate` (generates a fresh 2048-bit RSA keypair, encrypts the private side, returns the public key once for DNS publication), `templates` (CRUD + `/preview` server-side merge-tag render so the dashboard preview matches the worker's render), `campaigns` (CRUD + `/send-now` materializes recipients + flips status to SENDING + enqueues per-recipient `EMAIL_SEND` jobs / `/schedule` stores `scheduledFor` for the dispatcher / `/cancel` unblocks the cleanup), `suppressions` (list/add/remove with `(agencyId, email)` unique), `contacts` (list/add/update/delete + `/bulk` upsert for CSV import), and super-admin-only `admin/featured-listings` (CRUD with property tier-gate via `getCurrentPlanTier` so only PRO+ agencies can be featured).
- **Anonymous tracking endpoints** (`/api/email/*`). `GET /o/:tok` returns a 1×1 GIF + idempotently stamps `openedAt` and bumps `EmailCampaign.openedCount`. `GET /c/:tok?u=<url>` 302s to the original URL after stamping. `GET/POST /u/:tok` shows a confirmation page + writes `EmailSuppression(UNSUBSCRIBE)` + bumps the recipient's `Contact.unsubscribedAt` so they drop out of future audiences without a separate cleanup pass. All endpoints fail silently to keep them opaque to crawlers; counters use conditional updates so re-deliveries don't inflate stats.
- **Per-agency SMTP transport** (`apps/worker/src/processors/email-send/processor.ts`). One job = one `EmailCampaignRecipient`. Pipeline: load + validate status, suppression check (case-insensitive via Citext), build merge context (snapshotted `recipient.context` + recipient email + agency name + tracking pixel + unsubscribe URL), render subject + body via the shared `{{path.to.value}}` substitution (HTML-escaped for the body), rewrite `href="…"` through the click-tracking redirect (skipping anchors / `mailto:` / our own tracking URLs), append a 1×1 open-pixel, decrypt the agency's SMTP creds + (optional) DKIM private key from `AgencyEmailConfig`, send via nodemailer 6.x with `pool: true, maxConnections: 5` (one cached `Transporter` per agency for the worker process lifetime so reconnect overhead doesn't dominate). On send: stamp `sentAt` + `status=SENT` + `EmailCampaign.sentCount++`. On suppression hit: `status=FAILED` + `errorMessage="Suppressed"` (counted under `unsubscribedCount` since that's the user-visible bucket). On nodemailer error: throw → BullMQ retries (3 attempts, exponential 30s backoff). After every recipient finishes, `maybeFinalizeCampaign` flips `EmailCampaign.status` → SENT when `EmailCampaignRecipient(QUEUED)` count reaches zero (race-safe via `updateMany where status=SENDING`).
- **Campaign dispatcher** (`apps/worker/src/processors/campaign-dispatcher/processor.ts`). New `CAMPAIGN_DISPATCHER` BullMQ scheduler ticks every 5 min. Finds `SCHEDULED` campaigns past `scheduledFor`, materializes recipients from contacts / leads (skips suppressed addresses + null-email leads), flips status to `SENDING` via race-safe `updateMany(where: { status: "SCHEDULED" })`, and fans out per-recipient jobs onto the same `EMAIL_SEND` queue used by `/send-now`.
- **Featured listings — public surface**. `/api/public/featured-listings?surface=PUBLIC_HOME&locale=en&limit=6` returns position-ordered cards (active window only, ACTIVE+PUBLIC properties, `cache-control: max-age=60`). Public marketplace homepage now renders these in a 3-column grid above the search CTA; gracefully degrades to the unfeatured layout when the api is down.
- **Web marketing dashboard**. `/[locale]/dashboard/marketing` landing tile with 5 sub-sections; per-section pages for templates (with merge-tag hint), campaigns (with status-coloured badges, audience source + tag filter, send-now / cancel / delete actions), contacts (search by email/name + tag filter + add form + delete), and suppressions (manual add + remove). `/[locale]/dashboard/agency/email-config` has the SMTP form (password placeholder shows `(unchanged)` when persisted), test-send box, and DKIM rotate panel. `/[locale]/dashboard/admin/featured-listings` super-admin curation with surface filter + active-only toggle. Dashboard home + admin landing tiles added.
- **i18n**. New 4-locale `marketing` namespace in `apps/web/messages/{en,es,de,fr}.json`.

### Added (Sprint 7 — billing + plan-gating, slices 7.A–7.J)

- **Schema additions**. Migration `20260510152523_sprint_7_billing_vat` adds `Agency.billingEmail`, `Agency.vatNumber`, `Agency.vatCountryCode`, `Agency.taxIdValidated`. VAT is split into number + country code so we can fall back when a customer enters a number without prefix; `taxIdValidated` flips on the first Stripe-validated `customer.tax_id.{created,updated}` event. Existing `Plan`, `AgencySubscription`, `SubscriptionInvoice`, `ProcessedStripeEvent` models from Sprint 0 stay unchanged. Plans seeded earlier (FREE / PRO with `features` JSON matching PLAN §6 matrix).
- **Stripe SDK + idempotency wrapper** (`apps/api/src/lib/stripe.ts`). Memoized `getStripeClient(secretKey)` (pinned `apiVersion: "2026-04-22.dahlia"`, 3 network retries, 20s timeout). `BillingDisabledError` short-circuits all routes when `STRIPE_SECRET_KEY` is unset so dev environments without Stripe still boot. `processStripeEvent(event, handler)` writes a `ProcessedStripeEvent` row first; P2002 unique-violation on `stripeEventId` collapses duplicate deliveries to a no-op. New env vars: `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`, `STRIPE_PRICE_PRO_{MONTHLY,YEARLY}_{EUR,GBP}`, `STRIPE_TAX_ENABLED`. All optional in dev; routes 503 with `code: BILLING_DISABLED` when missing.
- **Plan-tier helpers** (`apps/api/src/modules/billing/plan-tier.ts`). `getCurrentPlanTier(agencyId)` reads `AgencySubscription`, honours manual grants (returns FREE when `grantedUntil` has lapsed), and falls back to FREE for `CANCELLED / INCOMPLETE / UNPAID / PAUSED`. `tierHasFeature(tier, feature)` centralises the PRO+ check. `requireFeature(request, feature)` throws `PlanRequiredError` (403 `code: PLAN_REQUIRED`); SUPER_ADMIN bypasses.
- **Billing API** (`/api/dashboard/billing/*`). `GET /summary` returns the effective tier + Stripe state + manual-grant fields + VAT block + `billingEnabled` + `hasStripeCustomer`. `GET /invoices` lists the last 50 `SubscriptionInvoice` rows. `PATCH /details` updates `billingEmail` / `vatNumber` / `vatCountryCode` and resets `taxIdValidated`. `POST /checkout` resolves-or-creates the Stripe Customer, creates a Checkout Session in subscription mode with `automatic_tax: { enabled: true }` + `tax_id_collection: { enabled: true }` + `customer_update: { address: 'auto', name: 'auto' }` when `STRIPE_TAX_ENABLED=true` (Stripe Tax handles VAT + reverse-charge for valid EU VAT IDs), returns the hosted URL. `POST /portal` returns a Stripe Customer Portal URL for self-serve plan changes / payment method / cancellation. AGENCY_ADMIN gating; SUPER_ADMIN may pass `?agencyId=`.
- **Stripe webhook receiver** (`/api/billing/webhooks/stripe`). Mounted under its own Fastify plugin so we can register a content-type-specific raw-body parser without breaking the main JSON parser. Skips registration when `STRIPE_SECRET_KEY` or `STRIPE_WEBHOOK_SECRET` is unset. Verifies `stripe-signature` via `stripe.webhooks.constructEvent`. All work flows through `processStripeEvent`. Handlers: `checkout.session.completed` (sanity-check); `customer.subscription.{created,updated}` (price → tier, cycle from recurring.interval, currency from price, status mapped to internal enum, `current_period_*` lifted from the first subscription item with legacy fallback — manual grants take precedence over Stripe state); `customer.subscription.deleted` flips to CANCELLED + FREE (unless granted manually); `invoice.{paid,payment_failed,finalized,voided}` upserts `SubscriptionInvoice` (tax computed as `total - subtotal` because Stripe v22+ removed the top-level `tax` field); `customer.tax_id.{created,updated}` flips `Agency.taxIdValidated` based on `verification.status === "verified"`. PLAN_CHANGED audit-log on every Stripe-driven tier flip.
- **Manual grant API + super-admin admin UI** (`/api/dashboard/admin/billing/*`). `GET /agencies` super-admin-only paginated list (cursor on `(createdAt desc, id desc)`, `q` filter on name/slug). `POST /grants` upserts `AgencySubscription` with `grantedManually=true` + `grantedReason` + optional `grantedUntil`; writes `AuditLog(PLAN_GRANTED_MANUALLY)` in the same transaction. `POST /grants/revoke` clears manual fields, falls back to FREE, writes `AuditLog(PLAN_REVOKED)`. Web `/[locale]/dashboard/admin/billing` lists all agencies with a `Grant…` `<details>` form per row (tier select + optional expiry + required reason) and a `Revoke` button. Admin landing tile.
- **PUBLIC visibility plan gate**. `apps/api/src/modules/properties/service.ts` calls `assertVisibilityAllowed` on create + on update only when `visibility` actually changes (keeps unrelated edits unblocked after a grant lapses). FREE agencies setting `visibility=PUBLIC` get `403 PLAN_REQUIRED`. SUPER_ADMIN bypasses. Web property form surfaces an inline hint pointing FREE users to Billing.
- **Web billing dashboard** (`/[locale]/dashboard/billing`). Server Component shows current tier via `PlanBadge`, status, period end (renew vs cancel-at-period-end), manual-grant note (with expiry), invoice table with Stripe-hosted invoice links, plus a `BillingDetailsForm` Client Component (`useActionState`) for billing-email / VAT. FREE+billing-enabled tier renders monthly + yearly EUR PRO upgrade buttons → `startCheckoutAction`; existing customers get a `Manage` button → `openPortalAction`. Both Server Actions resolve the hosted URL via the api and `redirect()` server-side. Dashboard home gets a Billing tile (AGENCY_ADMIN+SUPER_ADMIN only).
- **i18n**. New 4-locale `billing` namespace in `apps/web/messages/{en,es,de,fr}.json` covering plan/state strings, checkout success/cancel, billing-detail form, invoice table, and the `status.*` enum mapping.

### Added (Sprint 6 — viewing requests + deals + chat + notifications, slices 6.A–6.I)

- **`Notification` schema** (migration `20260510135140_sprint_6_notifications`). New model + `NotificationKind` enum (14 kinds covering viewing/deal/chat/lead/import lifecycle). Indexes on `(userId, createdAt desc, id desc)` for the cursor feed, `(userId, readAt)` for unread counts, `(emailedAt, createdAt)` for the digest worker scan. `targetKind`+`targetId` are stable pointers (e.g. `ViewingRequest`, `Deal`, `ChatThread`) so click-through links survive payload schema changes.
- **ViewingRequest workflow API**. `viewingRequestSchemas` namespace + `/api/dashboard/viewings` REST surface (list / detail / create / accept / decline / reschedule / cancel / outcome). Client info (name/email/phone/notes) AES-256-GCM-encrypted at rest via `@inmolink/auth`'s `encryptToString`/`decryptFromString` and only decrypted after the visibility check (`canAccess`). `expiresAt = now + AgencySettings.viewingResponseDays`. Accept auto-creates the unique VIEWING `ChatThread` between owner+introducer (idempotent — second accept on a reschedule reuses the existing `chatThreadId`). System chat messages (`systemKind = "viewing_proposed"`) emitted on accept/reschedule when the actor includes a `responseMessage`. `callerActions` server-computed and returned with every read so the UI doesn't replicate the state machine. New worker scheduler `VIEWING_EXPIRE` (hourly cron `0 0 * * * *`) sweeps stale `PENDING` rows past `expiresAt` to `EXPIRED` in batches of 200, emitting one notification per side.
- **Deal handshake API**. `dealSchemas` + `/api/dashboard/deals` (list / detail / create / confirm / dispute / cancel) + super-admin-only `/disputes` queue + `/:id/resolve-dispute`. Money math is BigInt cents with half-up rounding to avoid float drift; commission% + introducerShare% are snapshotted from the listing agency's `AgencySettings` at submit time (per-deal overrides allowed). Submit auto-confirms the submitter side and sets status to `PENDING_<otherSide>`. Confirm by the other side flips to `CONFIRMED` and notifies both. Dispute writes `disputeReason` + `disputeOpenedById`, notifies the counterparty + every active super-admin, and writes an `AuditLog(DEAL_DISPUTED)`. Resolve (super-admin only) sets `disputeResolvedAt`, picks `CONFIRMED | CANCELLED` outcome, notifies both parties, and writes `AuditLog(DEAL_DISPUTE_RESOLVED)`.
- **Socket.io with Redis adapter** (PLAN §11.8). `socket.io` + `@socket.io/redis-adapter` mounted on `app.server` from a Fastify `onReady` hook so the HTTP server is bound first. Auth.js v5 cookie handshake mirrors the REST plugin (`installAuth`) — same `decode({ token, secret, salt })` against both `authjs.session-token` and `__Secure-authjs.session-token` candidates. Two dedicated Redis duplicates (pub/sub) drive the adapter so multi-instance scale-out is a config flip, not a code change. Each connection auto-joins `user:<id>` (per-user fanout backbone) and the `Server` is exposed via `app.io` with a typed `AppIOServer` wrapper that locks `socket.data.user` to the decoded session.
- **Chat REST + Socket.io fanout**. `chatSchemas` + `/api/dashboard/chat/threads` (list with cursor + per-thread `unreadCount`), `/threads/direct` (`getOrCreate` via the `@@unique(kind, userMin, userMax)` constraint), `/threads/:id`, `/threads/:id/messages` (cursor history), `/threads/:id/messages` POST (canonical write surface), `/threads/:id/read` (mark-read upserts `ChatThreadRead`). The HTTP POST persists, bumps `lastMessageAt` + `lastMessagePreview`, auto-marks the sender's read pointer at their own message, emits a `Notification(CHAT_MESSAGE)`, then fans out via Socket.io: `chat:message:new` to `thread:<id>` for any subscribed clients + `notification:new` to the recipient's `user:<id>` so the bell badge updates even when the recipient isn't on the chat page.
- **Notification digest worker**. New `NOTIFICATION_DIGEST` BullMQ scheduler in `apps/worker` ticking hourly at `:05` (offset from `VIEWING_EXPIRE` so they don't compete for connection burst). `groupBy({ userId, _min.createdAt })` finds users with pending rows, then per-user thresholds respect `UserSettings.emailDigestFrequency` — `INSTANT` ships every tick, `DAILY` only when oldest pending row is ≥ 24 h, `WEEKLY` ≥ 7 d. HTML+text body via Resend (`POST https://api.resend.com/emails`); soft-fails when `RESEND_API_KEY` unset (logs the body) so dev works offline. Marks `Notification.emailedAt` only on Resend ack so transient failures retry on the next tick. Inactive / deleted users get their pending rows marked emailed-at to avoid an unbounded retry loop. Sprint 8 will rebuild this around per-agency SMTP via `AgencyEmailConfig`.
- **`/api/dashboard/notifications`**. List endpoint with cursor + `unreadOnly` filter + `unreadCount` per response (drives the dashboard bell badge). Plus `POST /read-all` and `POST /:id/read` endpoints that scope updates by `userId` so the caller can never read someone else's row.
- **Web ViewingRequest UI**. `/[locale]/dashboard/viewings` list (filter by role: `owner` / `introducer` / `all`); `/new` form with up-to-3 preferred dates + encrypted client fields; `/[id]` detail with property + parties + decrypted client + schedule + WhatsApp/mailto handoff buttons (using `wa.me/<digits-only>`) + chat link if a thread exists. `ViewingActions` Client Component renders only the buttons the server says are allowed (`callerActions.canAccept` / `canDecline` / `canReschedule` / `canCancel` / `canSetOutcome` / `canSubmitDeal`); inline panels for accept/reschedule (datetime + meeting point), decline (optional reason), and outcome (5-way enum). Server Actions wrap each transition with `apiFetch` and `revalidatePath` on success.
- **Web Deal UI + super-admin disputes**. `/[locale]/dashboard/deals` list, `/new` form with currency + commission% + introducerShare% overrides, `/[id]` detail with money breakdown rendered via locale-aware `Intl.NumberFormat`. `DealActions` shows confirm / dispute / cancel by `callerActions`; `resolveDispute` panel (CONFIRMED | CANCELLED outcome + notes) only renders for super-admins. New `/[locale]/dashboard/admin/disputes` queue lists all `DISPUTED` deals with the dispute reason preview + click-through. Admin landing tile added.
- **Web chat UI**. `/[locale]/dashboard/chat` thread list with last-message preview + unread badge. `/[locale]/dashboard/chat/[id]` SSR-fetches the latest 50 messages, hydrates a `ChatPanel` Client Component that opens a Socket.io connection to the api (cookie auth via `withCredentials: true`), subscribes to `thread:<id>`, and inserts new messages on receipt. Sender's own messages are POSTed via REST (canonical write); the socket fanout still arrives so the dedupe check (`prev.some(m => m.id === id)`) drops the second copy. Auto mark-read upserts `ChatThreadRead` whenever the message count changes. WhatsApp handoff link surfaces on the viewing detail page; per-locale strings flow through `next-intl`.
- **Web notifications surface**. `/[locale]/dashboard/notifications` inbox with `unreadOnly` filter, mark-all-read button (Server Action), and click-through routing (`ViewingRequest` → `/dashboard/viewings/<id>`, `Deal` → `/dashboard/deals/<id>`, `ChatThread` → `/dashboard/chat/<id>`). Bell badge on dashboard home with the unread count (soft-fails to `0` on api outage so the dashboard remains usable).
- **i18n**. New 4-locale `viewings`, `deals`, `chat`, `notifications` namespaces in `apps/web/messages/{en,es,de,fr}.json`. ES translations done; DE + FR seeded with translations covering the most-used keys; full polish pass deferred to Sprint 12.

### Added (Sprint 5 — imports, slices 5.A–5.H)

- **Kyero streaming SAX connector** (`8e75074`). New `@inmolink/imports` Kyero adapter parses Kyero v3 XML feeds with a state-machine SAX walker — never buffers the whole feed (production Kyero feeds reach 100+ MB). Yields one `NormalizedListing` per `</property>` close; consumer pulls listings via AsyncIterable; the parser pauses when the `AsyncQueue` queue exceeds 50 buffered items. Locale-keyed `<title>`, `<desc>`, and per-feature names land in `translations` and `FeatureName.perLocale`. Image URLs preserved as-is so the worker hashes the bytes (the `?v=` cache-buster doesn't poison dedup). Strips `(Province)` suffix; falls back to `<id>` when `<ref>` is empty (2/270 in the production sample). 10 unit tests against `samples/feeds/kyero-sample.xml` parse all 270 properties + 8,962 image URLs and lock the price/transaction-type/sourceUpdatedAt mapping.
- **Resale Online + Generic XML connectors** (`3b6bece`). Generic XML engine is config-driven: agency-supplied path → field mappings walk the same SAX state machine as Kyero (same `AsyncQueue`, same backpressure, same `finalize` gate). Mapping dispatched on closing-tag name; locale captured statically or via XML attribute (`<title language="en">`). Resale Online ships as a baked-in preset over the engine — overlaps Kyero in shape (locale-keyed text, features-as-wrapper, `<images>/<image>`) but differs in tag names (the same agencies that publish Kyero feeds often back-end onto Resale Online — the Kyero sample's image CDN is `cdn.resales-online.com`). Registry returns a fresh connector per `FeedConnectorKind`. GENERIC_XML requires a mapping config; Kyero/Resale need none. 3 additional tests for Generic XML + Resale.
- **FeedTypeMap mapping table + matchers** (`831f4b4`). Schema adds `FeedTypeMap(kind, sourceLabel, propertyTypeId)` unique on `(kind, sourceLabel)` with `sourceLabel` canonicalised (trimmed + lower-cased) on every write. Migration `20260510125707_sprint_5_feed_type_map`. Matcher helpers in `@inmolink/imports` (consumed by api + worker): `findPropertyTypeForFeed` (FeedTypeMap → translation fallback → null); `findLocationForTown` (case-insensitive city match scoped to country, province as tie-breaker for ambiguous town names like Córdoba in ES vs AR, surfaces `ambiguous` flag when no winner); `findFeatureIdsByName` (any-locale translation match, deduplicates feature ids and surfaces unmatched names so the super-admin can extend the catalog). Super-admin API at `/api/dashboard/admin/feed-type-maps` (CRUD; P2002 surfaces as 409). 10 matcher tests.
- **Worker import processor + scheduler** (`c4e2ee8`). New `FEED_IMPORT` BullMQ processor wires connectors + matchers + the existing dedup-aware `MediaObject` pipeline into a single transactional run. Lifecycle: atomic mutex via `UPDATE ... WHERE isLocked=false` (0 rows → another run in flight, exit cleanly); resolve / create FeedRun (api pre-creates QUEUED for MANUAL; CRON ticks lack a runId so the worker creates one); decrypt feed credentials (AES-256-GCM via `@inmolink/auth`); stream listings; per listing `upsertPropertyFromListing` (matches type + location + features, applies `lockedFields` field-level locks per PLAN row 16, drops to DRAFT when type / location unmatched on first import); image attach pass per property (downloads each URL with a 25 MB cap, SHA-256 hashes, bumps existing `MediaObject.refCount` or PUTs to canonical key + creates row + enqueues eager variants matching the dashboard upload flow's jobIds). ### Added (Sprint 1 — slice E, property-image attach + media cleanup)

- **Property-image attach API** under `/api/dashboard/properties/:id/images`:
  - `POST` — bulk attach 1–50 MediaObjects (validates each is an `image/*` MIME, rejects unknown ids). One transaction per request: creates `PropertyImage` rows + bumps `MediaObject.refCount` + clears the 24h orphan-grace `scheduledDeleteAt`. Cover-uniqueness enforced (only one `isCover=true` per property; old cover gets unset in the same tx).
  - `PATCH /:imageId` — alt text, position, isCover.
  - `DELETE /:imageId` — drops the row + decrements refCount; if it hits 0 the service sets `scheduledDeleteAt = NOW() + 7d` for the cleanup worker.

- **`MEDIA_CLEANUP` worker** (`apps/worker/src/processors/media-cleanup`) — dedicated processor + repeatable scheduler. Runs daily at 03:00:00 via `Queue.upsertJobScheduler('media-cleanup-daily', { pattern: '0 0 3 * * *' }, ...)` (BullMQ 6-field cron, seconds first). Idempotent — every worker boot re-upserts the same scheduler id, so adding pods needs no ops step.
  - Pass 1 — MediaObject orphans (`refCount<=0` + `scheduledDeleteAt<=NOW()`): decrements refCount on every variant whose source points here (when a variant drops to 0, schedule its own delete = NOW()+7d), deletes the source R2 blob, then deletes the row. Variant rows survive parent deletion thanks to the FK SetNull.
  - Pass 2 — MediaVariant orphans (same WHERE): deletes the variant blob, then the row.
  - Storage delete failures are logged but don't block DB GC. Batch size capped at 500 rows/pass to bound a single tick's runtime.
